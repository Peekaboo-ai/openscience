# Shell latency and follow-up delivery

## September 23 robustness audit

Compared OpenScience's native shell/authority lifecycle, OpenCode `2406400f0aeb07b36d0495af4e05aaca49159832` terminal and permission implementation, and ZCode's `ConversationComposer.tsx` and `TerminalSession.tsx`. Keep the existing execution leases, credential filtering, durable queue and cancellation ownership. Reuse the native dropdown and separate default guidance from explicit queued delivery, matching the composer semantics rather than adding mode buttons that appear to send without doing so.

The remaining Conda delay was reproducible in the actual sandboxed Bash tool: activation printed its first marker but exceeded a 20-second deadline. In the same sandbox, a controlled `conda shell.posix activate onezone` probe took 7.429 seconds normally, but exceeded 15 seconds with the forced per-session `PYTHONPYCACHEPREFIX`. Ordinary Shell now reads the installed bytecode and disables bytecode writes. Explicit managed Python tools retain their existing overlay. Conda runtime subtrees are exposed read-only, matching Terminal; this does not grant access to surrounding home directories.

Recorded tool-part time is not execution time: one 144.7-second part spent only 7.2 seconds in execution; another 272.9-second call was rejected at permission. The interface now labels pending approval distinctly and shows timeout/cancellation reasons. Exhaustive `find` scans of shared cluster filesystems can still take time and remain subject to the configured deadline.

The old local log contained 1,910 reads of a deleted session, plus cancelled remote requests. This is evidence of stale polling, not proof of the original crash. Deleted sessions now stop polling and leave the active route. Remote HTTP response streams are created only after headers, callback errors cannot close unrelated SSH requests, PTY disconnect races cannot interrupt deletion cleanup, and the remote worker has the same persistent background-error logging boundary as the normal server.

Timeline remains mounted while hidden. Action pages publish independently of workbench summaries; refresh retains existing data and summary requests are single-flight. Permission decisions disable immediately, expose errors for retry, and remove the card only after the backend confirms the decision.

Terminal verification uses real SCNet PTY output rendered in xterm/headless, checking intact input before execution at widths 52, 100, 42 and 80, including a resize to 46 columns during typing. Browser verification caught a startup race missed by those checks: the browser/replay ring reported 66×45, but `stty size` inside the actual shell remained 80×24. The initial resize could occur before bubblewrap's inner `script` bridge existed, losing its SIGWINCH; identical later sizes were then skipped. The resize acknowledgment now waits for bridge output before applying/relaying geometry, preserves startup output at its original size, and re-applies identical requested sizes. Deleted/exited PTYs cannot be resurrected by delayed resize completion. Startup has a bounded 30-second wait. The live regression now resizes immediately after creation, before waiting for a prompt. Parent `COLUMNS`/`LINES` are discarded and Bash enables `checkwinsize`.

It returned the selected onezone prefix and R executable, `PYCACHE=unset`, and the final marker. Permission approval removed its card immediately after acknowledgment. Deleting a test session during continuous terminal output reclaimed its PTY while the remote health endpoint remained available. Browser Timeline preserved its filter and loaded rows across a Terminal round trip. Cluster queries, Conda enumeration and recorded geometry replay also passed in the sandbox.

Installed `2.0.127-workspaces.20260923.2` includes the startup geometry correction. The real browser terminal reported `stty size` of `45 66`, matching its 66-column, 45-row replay geometry. Character-by-character multiline input rendered intact and executed both before and after `conda activate onezone`. The updated immediate-resize, resize-during-input and delete-during-output regression passed, as did sandboxed cluster queries, Conda enumeration and geometry replay. Both local and remote health endpoints reported the new version. One initial connection's sandbox probe timed out and correctly refused execution; reconnecting restored verified bubblewrap availability without changing access policy. Direct SSH probes also succeeded, so that transient failure is recorded separately from the corrected terminal geometry race.

The SCNet run `ses_f3b28f57bffedgfvjfcrqutufk` spent 568.6 seconds on a Conda discovery call with a requested 120-second timeout. Its provenance interval was only 46.1 seconds; approximately 522 seconds occurred before command registration. Bash eagerly called `pythonSubprocessRuntime()`, which can provision or repair the complete science starter. The timeout was not installed until after that work. The following activation call also selected a managed Python wrapper despite explicitly activating `onezone`.

Ordinary Bash now uses the host environment and never provisions Python. Explicit `environment: "python"` reuses an existing interpreter and the project package overlay without starter maintenance. The canonical Python kernel retains its provisioning and verification contract. Linux command supervisors dispatch through bootstrap before loading the application graph, retaining the existing registration gate and subreaper ownership.

An execution lifecycle starts after permission approval. Preparation, launch and execution share one deadline; read-only waits can be interrupted, spawn boundaries check cancellation, and durable Linux release checks the same signal. Live metadata reports preparation, environment selection, output observation, launch, running and result collection. A command without an explicit timeout defaults to 120 seconds; zero explicitly disables the deadline. OS-level cleanup still completes before returning, so a timeout is a stop request, not permission to abandon a child process.

The follow-up design was checked against OpenScience's `RuntimeRuns` admission journal and `SessionPrompt` step loop, ZCode's `commands/handlers/queue.ts` promotion/stop barriers and complete-input preservation, and OpenCode's `packages/app/src/components/prompt-input/submit.ts` queue routing and failure restoration. The implementation reuses this repository's leases, storage, run receipts and UI components rather than importing another framework.

Guidance joins an active run through an idempotent transcript admission. It is also accepted while that run holds its preparation reservation. A separate durable queue stores complete inputs. Queue mutations require a revision, so stale windows cannot overwrite edits. Dispatch intents are persisted before runtime admission and always reuse the same request ID. Failed or cancelled runs pause pending work; process identity checks pause orphaned queues after restart. Only a completed run advances the next item. Queueing is negotiated with the connected backend and never falls back to an immediate legacy prompt.

Validation covers real local-provider runs, order and deduplication, rich input preservation, cancellation, restart recovery, preparation deadlines, explicit shell environment selection and independent-process admission. Remote acceptance must also measure actual Conda discovery/activation and interpreter identity using the packaged Linux runtime; local tests alone cannot establish remote filesystem or scheduler performance.

Packaged SCNet acceptance on 2026-09-22 used a dedicated test project. Its unavailable bubblewrap backend required the previously authorized temporary Full access mode; the original Approve mode with sandbox enabled was restored. Ordinary shell preparation reached execution in approximately 0.43 seconds. A combined environment-list/activation command hit its 30-second deadline and settled after process cleanup at 36.4 seconds. A separate activation succeeded: Conda reported 8.403 seconds, the complete tool call took 14.166 seconds, and both `command -v python` and `sys.executable` pointed to `miniconda3/envs/onezone/bin/python`. Direct SSH activation also succeeded (6.396 seconds); environment enumeration and the remote filesystem can still contribute latency. These measurements do not imply every command or model response completes within the same duration.

Linux regression verification used Bun 1.3.14, Python 3.12 and ripgrep 14.1.1. The host's default Python 3.6 cannot run the Python SDK conformance fixture, and missing ripgrep makes the real glob fixture download a dependency; supplying the existing modern Python and official ripgrep resolves those harness failures. Windows assertions passed, but the combined backend suite encountered EBUSY while removing temporary files. Frontend regression verifies that queue polling preserves the active editor, focus and selection, following the same keyed `reconcile` approach as OpenScience's message and session stores. Older poll responses cannot replace a newer queue revision.
