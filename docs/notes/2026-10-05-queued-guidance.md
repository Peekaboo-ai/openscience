# 运行中消息排队与引导

## 用户交互

- Research 会话运行中，Enter 和发送按钮默认加入持久队列；空闲时仍直接启动任务。
- 输入框上方显示紧凑队列条及待执行数量。每条可引导当前任务、删除，或在更多菜单中编辑、排序、暂停/恢复队列。
- Ctrl/⌘+Enter 或发送菜单的“引导当前任务”直接发送补充指令。Shift+Enter 保持换行。
- 编辑只修改正文，保留附件、文件评论、模型及推理设置。其他窗口修改了同一正文时，保留本地草稿并显式选择载入最新内容或保留自己的修改。
- 等待首条任务准入时可继续编辑下一条草稿；发送暂时禁用，避免后续队列抢先启动。此状态随新建会话路由转移，停止按钮与 Escape 仍可用。
- 队列条沿用主题、按钮及菜单样式；无障碍状态播报只覆盖状态与数量。当前会话排队成功不堆叠遮挡输入框的通知。

## 协议与可靠性

复用现有 `/runtime/queue` 持久队列，新增 `PATCH` 变更 `{ type: "guide", id, runID }`。快照提供 `activeRunID` 和 `dispatching`，分别表示可引导的当前运行和已认领的消息。

晋级由后端核对指定运行并保存回执。任务已结束或被替换时，不能把引导意外启动为新任务；重复请求不能重复写入对话。附件准备后的实际消息与部件标识先持久化，再写入对话，以恢复消息/附件部分写入或回执丢失的中断窗口。附件授权与读取移到会话锁外，提交时重新核对原运行；停止、取消及自然结束可撤销这次引导的待决授权。

队列读取、更新均设整体超时；临时失败退避重试，旧服务不支持队列时停止轮询。切换会话后忽略旧请求结果，队列版本变化不覆盖编辑中的草稿。旧服务无法把排队请求静默降级为立即引导。

Shell 等没有持久运行回执的旧控制器占用会话时，队列明确暂停并提示命令结束后手动继续。取消、失败和服务重启继续保留原有暂停语义。

## 验证与范围

验证包含真实 SDK HTTP 请求、后端真实存储和运行接收、组件 DOM 交互及生产构建的 Edge 浏览器。浏览器使用隔离假服务，不连接用户科研项目、不调用付费模型，覆盖默认发送、快捷键、消息管理、编辑冲突、新建会话准入竞态及停止后的草稿保护，并检查浅色/深色和窄屏布局。

前端全套 1425 项通过，SDK 31 项、文档 7 项通过；整仓类型检查的 7 个任务全部通过。生产构建成功，Edge 完整页面回归 12 项通过且无页面异常。队列组件的 16 项行为测试包含超时恢复、旧服务兼容、跨会话响应隔离及编辑冲突；另有真实 HTTP 测试验证发送入口和附件参数。

后端最终串行回归 101 项通过、0 失败、512 个断言，覆盖 18 个文件：完整 runtime 套件、附件处理、提示取消、推理设置、提交后停止及控制器归属。真实文件权限测试覆盖停止、自然完成、用户拒绝，以及拒绝后继续编辑/删除；两项确定性收尾竞态测试确认引导成功或原运行结束时被拒绝后，剩余队列均会继续推进。delegation 测试保留原有 10 秒上限和全部终态断言，补充等待工具终态落盘，避免进程先退出造成误报。

本轮保留上一阶段工程审计的未提交改动。没有重启用户正在运行的服务、提交或推送代码；新增后端接口需要由更新后的后端进程提供。
