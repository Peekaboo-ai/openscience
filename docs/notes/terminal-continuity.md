# Terminal and conversation continuity

The terminal's frontend and backend must agree on geometry before input is sent. Independent HTTP resize requests could finish in the wrong order over SSH. The previous renderer also reflowed the cursor line before Bash/readline redrew its wrapped prompt, overwriting the preceding output. The terminal now uses xterm with cursor-line reflow disabled, keeping native fonts and theme colors. It measures through one animation-frame scheduler, ignores hidden terminals, waits for the selected font before measuring, coalesces sizes with only one request in flight, and waits for acknowledgement before replay or input. Unmounting a view remembers its dimensions without writing an obsolete size back to the PTY. Background PTY hydration keeps its ready state and reconciles rows by process ID.

Negotiating `replay=geometry-v1` on the PTY WebSocket adds binary resize/ready control frames around the unchanged text stream. Output chunks retain their original column and row counts, with bounded metadata, so reconnecting at another viewport size does not reinterpret historical cursor movement at the wrong width. The client drains queued text before each historical resize and suppresses replay-generated terminal replies and size writes. Older clients still receive plain text; newer clients can connect to older servers. The remote gateway already preserves text/binary frame identity.

Provider-auth revisions formerly fell through to full instance disposal, which killed PTYs even though their environments contain no provider credentials. They now retain project instances, invalidate provider caches through the existing refresh handlers, interrupt active model turns, stop credential-bearing commands and compute jobs, close MCP transports, and retain the credential-process ledger revokers. Account changes and project trust/access revocation keep their existing reach. Windows ownership launchers enter before application configuration because the filtered PTY environment intentionally excludes the normal user profile; `.exe` shell names receive the same clean startup arguments as POSIX names.

Conversation snapshots belong to WorkspaceProvider, outside backend-scoped page mounts. Keys include backend URL, project, search, and limit; inactive snapshots are bounded to 100 entries. Fold/unfold reuses loaded rows and joins pending reads. Refresh failures retain rows. Mutation invalidation rejects old in-flight snapshots and schedules a fresh read. Active entries cannot be evicted; disposal aborts requests. Only cold loads that outlast the short feedback delay show the loading hint.

Regression coverage includes ordered geometry writes and retries, cache isolation and stale-response races, real credential process teardown, and adding/rotating/removing fake model credentials while checking the same native PTY PID and shell variable. `tooling/repo/verify-terminal-continuity.ts` exercises an explicitly selected remote test project with sandboxing enabled; it verifies sizes and captures line endings around cluster and Conda output without changing the user's shell profiles.

Local validation on 2026-09-22: 32 backend and 23 frontend regression tests passed, together with backend, workspace and generated SDK type checks. Windows and Linux packages were built as `2.0.127-workspaces.20260922.7`. The installed browser UI retained Conda table rows and preceding output through narrow/full-screen resizing, refresh and switching between two terminal tabs; terminal search and repeated sidebar expansion also passed. This SCNet UI run used the previously authorized host mode only for the dedicated test project after the login node's bubblewrap probe timed out. Both test terminals and the test conversation were removed, and the original `approve` mode with sandboxing enabled was restored.
