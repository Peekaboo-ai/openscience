# Windows 消息发送长路径修复

## 原因

发送消息首先创建持久化运行回执，路径包含项目 ID、会话哈希和运行哈希。
Storage.publish 又在目标文件名后追加进程号和 UUID 作为同目录临时文件。
Windows 上 Bun.write 对此普通长路径报 ENAMETOOLONG，导致请求在调用供应商之前失败。
界面表现为 Send prompt failed，堆栈指向 storage.ts 的 publish。

## 修复

临时文件改用支持 Windows 长路径的 fs.writeFile 创建，随后仍通过同目录 rename 原子发布。
保留跨进程写锁；使用排他创建及 owner-only 文件权限；写入或重命名失败时清理本次临时文件。
项目目录、历史记录、模型配置及密钥无需迁移或修改。

## 验证

  长路径写入、读取、更新、upsert、列表和删除，无临时文件残留。
- 长路径、写入合并、跨进程锁和临时文件列表测试共 10 项通过；后端类型检查通过。
- 更广的存储测试另有两项使用 Windows 不支持的 SIGSTOP，未修改这些 POSIX 测试。

  因此不将该测试文件计为通过。
