# OneLab 工作台可靠性审计

审计日期：2026-10-02 至 2026-10-03。对象：`dev` 分支上的当前工作目录，基线提交 `8157a3c7`。

本轮完成了代码审查、缺陷修复、故障注入回归和浏览器验证，保留现有功能模块及此前的本地修改。检查重点是会话与项目切换、异步请求归属、失败恢复、远端通信、科研结果可信展示，以及设置和弹窗的生命周期。

## 方法与范围

- 开始时保存工作区状态与已有差异，避免将前序功能改动误归为本轮审计成果。
- 并行检查运行时与终端、Files/Results 与科学渲染、设置与项目连接；交叉复核修复后的异步边界。
- 参考本地 ZCode 的 `sessionDataLayer.ts`、`SessionPane.tsx` 中会话绑定与草稿恢复方式，以及仓库现有 OpenCode harness 对比笔记与本地参考源码。应用相应的归属、取消、恢复原则，没有复制上游代码或替换 OneLab 功能。
- 使用真实 Solid 组件与 SDK 实现进行测试；浏览器测试只创建临时空会话，拦截模型调用与故障响应，并在结束时清理会话。
- 未启动真实科研作业、调用付费模型、修改供应商凭据或远端研究数据。未重启现有前后端进程。

## 已修复的问题

### 会话、发送与草稿

| 触发场景                                        | 原有影响                                     | 修复结果                                                                           |
| ----------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------- |
| A 会话发送后切到 B，A 的请求稍后失败            | 失败恢复可能修改当前输入框                   | 捕获原会话草稿与版本，只恢复原会话，保留后来输入或发送的内容                       |
| 新会话已创建，但首条消息失败                    | 草稿可能留在新建页；工作树切换后作用域不一致 | 草稿转移到新会话和目标工作树，保留远端服务器标识                                   |
| 会话历史已出现，元数据仍在加载时点击发送        | 提交可能静默丢失                             | 显示提交状态，等待原会话加载，失败时恢复草稿并解释错误                             |
| 连续发送的请求全部失败                          | 乐观 busy 状态残留                           | 跟踪整组提交，最后一个失败收尾时恢复最初的空闲状态；已有运行或成功提交不被错误置闲 |
| 连续发送后，在工作树准备或能力协商阶段点击 Stop | 只取消一个请求，其他请求可能随后开始         | 取消整组预提交操作，恢复最新草稿；已开始的运行继续使用服务端取消接口               |
| 附件读取期间切换会话                            | 附件可能落入后来打开的输入框                 | 一批附件始终写入选择时的草稿                                                       |
| 能力协商请求不返回                              | 发送持续等待                                 | 本地与远端采用有限读取预算；没有对可能已执行的 POST 自动重放                       |

主要实现：`prompt-input.tsx`、`context/prompt.tsx`、`prompt-submission.ts`、`prompt-pending.ts`、`prompt-activity.ts`、`prompt-runtime.ts` 和 `utils/project-route.ts`。

### 后端、SSH 与终端

| 触发场景                           | 原有影响                                      | 修复结果                                                               |
| ---------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------- |
| 旧运行的异步收尾晚于下一轮启动     | 旧失败可能暂停新一轮消息队列                  | 在队列锁内检查运行与 barrier 的归属，再执行暂停                        |
| SSH 子进程停止读取输入，写管道堵塞 | 调用先等待写入，超时或取消仍无法返回          | 请求结果独立于写入完成，取消、超时和断连可以及时结束等待               |
| 终端重连替换原有 Solid 状态对象    | 删除旧终端时读到被原位更新的新 ID，误删新终端 | 先保存旧身份，再查当前标签位置；关闭、重排、重复重连时清理迟到替代进程 |

主要实现：`backend/cli/src/runtime/queue.ts`、`backend/cli/src/remote/client.ts`、`context/terminal.tsx`。SSH 回归包含实际子进程停止读取输入和大请求堵塞的场景。

### Files、Results 与科学预览

- Results 重命名、删除、下载与点击时的服务器、项目、制品绑定。迟到响应不能改新预览标题、关闭其他制品标签或解锁更新的操作。
- 科学容器检查的资源身份包含服务器和项目；切换或关闭预览取消旧等待，超时后可重试。
- Results 与 Trash 列表读取覆盖响应头和响应体的期限；一个列表失败时，另一个成功列表仍可使用。
- 文件权限元数据、普通目录、Modal 来源与 Trash 列表采用有限请求预算，并在切换或卸载时取消。已用尽期限的请求直接展示重试，不再重复等待一整段超时。
- 保留现有结果卡片、会话筛选、缩略图、下载归档、科学渲染和来源导航。

主要实现：`artifacts/actions.ts`、`artifacts/resource.ts`、`StoredArtifactView.tsx`、`atlas/files/metadata.ts`、`FilesPane.tsx`、`science/formats/inspection.ts`、`BinaryScienceView.tsx`。

### 设置、项目与导航

- 目录浏览的迟到响应不再覆盖用户手动输入；浏览期间不能提交过时路径，关闭项目对话框后不能因后台完成而突然导航。
- 恢复或删除最后一个归档会话后，仍保留退出归档列表的入口。
- Worker model 保存期间禁止并发覆盖，失败后恢复选项并重新启用控件。
- Usage Stats 输入无效日期时取消原查询；切换服务器后清理旧报表，即使当前日期仍无效，也不会显示另一服务器的统计。
- DialogProvider 卸载时释放独立渲染根、动画定时器和旧句柄，避免关闭后的弹层或回调残留。
- 本轮沿用现有 UI 组件和主题；将新增界面的硬编码颜色、字体粗细及未定义 token 引用归入现有语义变量，修复模型切换提示的分隔线、悬停和焦点样式。

主要实现：`workspaces/ProjectDialog.tsx`、`Sidebar.tsx`、`components/settings/Models.tsx`、`UsageStats.tsx`、`frontend/ui/src/context/dialog.tsx` 及相关 CSS。

### Autoresearch 与完成通知

- Pause、Resume、Halt、发送及撤回 directive 检查 HTTP 状态；失败不会被当作成功，控制区域显示错误与可重试状态。
- 同一研究的写操作去重，发送失败保留 directive；迟到成功不能清空新输入或另一研究的草稿。
- 按项目作用域挂载研究视图，释放旧请求；概览、曲线和指标选项按研究、运行及指标归属显示。切换 accuracy 到 loss 时不会继续用旧 accuracy 曲线冒充新指标。
- 科研数据读取保留匹配的历史快照并提供重试，GPU 轮询不重叠。
- 失败或取消后的 `session.idle` 不再触发成功完成提醒，重复 idle 不重复通知。
- 保留每个 `busy → idle` 生命周期事件，避免同一帧内状态合并使下一轮完成通知丢失；消息内容和 LSP 快照仍可合并。

主要实现：`AutoresearchPane.tsx`、`notification-lifecycle.ts`、`notification.tsx`、`global-event-buffer.ts`、`global-sdk.tsx`。
