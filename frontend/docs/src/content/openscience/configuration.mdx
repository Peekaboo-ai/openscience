Use Customize for everyday settings. Configuration files are useful when you want to review settings as text or share a project setup.

## Memory

Open **Settings → Memory** to save preferences, project background, lab conventions, and cautions. Select a scope, choose **Add memory**, and enter a short title and the information to remember. Saved notes are considered for the next model request, including the next step of a running conversation; they do not change requests already sent to a provider.

| Scope | Applies to |
| --- | --- |
| Global | Every project on the currently selected server. |
| Project | Every conversation in the selected project. |
| Session | The selected conversation and its delegated child sessions. Sibling conversations are separate. |

The page defaults to the current conversation when one is available. A new conversation without a session ID can use global or project notes; choose an existing session to save a session note. **Include inherited** shows notes from broader scopes alongside the current scope. **All saved memories** lets you find and delete notes even after their original project or session has been removed.

The **Project** selector follows the workspace sidebar: it lists active local projects and configured remote projects, including disconnected ones. Choosing a remote project loads its own memories and sessions without changing the conversation you are viewing. For a disconnected project, choose **Connect** or **Retry connection**; connection runs in the background, and you can select another project while it completes. **Global** and **All saved memories** include a **Memory location** selector for switching between local and remote stores. Archived projects and internal backend directories are excluded from the project picker; existing notes remain accessible through **All saved memories** on their original server.

Categories organize notes across scopes. Create or edit a category to set its description and **Auto-recall**. Turning Auto-recall off retains searchable notes without adding them to model context. The main Memory switch pauses all recall. Each note also has its own switch and optional expiration, entered in your local time. Notes are saved explicitly in Settings; category descriptions do not enable automatic note writing by the model.

You can switch categories, search, or browse another scope/project while editing.
An unfinished draft stays available through **Resume editing**; browsing does not
change its **Save in** destination. Local and remote drafts remain separate and
survive a temporary reconnection. **Discard draft** removes an unfinished draft;
opening another editor first offers to keep or discard it. Drafts are kept in
the current settings panel, not saved permanently: choose **Save** before
reloading or leaving the app. Controls are temporarily disabled during a write
or an explicit confirmation, and become available again if a save fails.

For notes with the same title in the same category, session notes override project notes, which override global notes. Titles are compared after trimming, Unicode normalization, and case folding. Different titles remain independent, so adding a project preference does not remove every global note in its category. Disabled or expired notes do not override active defaults.

Expand **Context preview** to inspect included, inherited, overridden, and omitted notes, or view the exact text added to context. Recall prioritizes more specific scopes and recently edited notes, with a limit of 20 notes and 12,000 characters including their context wrapper. Whole notes are omitted when a limit is reached; their contents are never silently cut. Up to 500 notes and 24 categories can be stored, with 4,000 characters per note. Current explicit requests take precedence, and memories never grant execution permissions.

Memories persist in `memory.json` in the server's data directory (shown in Settings → Storage). Local and remote servers have separate stores. Connecting a remote project does not copy local memories to it. Updates use atomic writes and revision checks; if another window changed memory, refresh and review the preserved draft before saving again. Deletion requires confirmation and affects saved context only, not past conversations. Clearing a scope preserves inherited notes.

Existing `AGENTS.md`, instruction files, skills, and project settings continue to work alongside Memory. If the memory file cannot be read, Settings reports the error and preserves the file; research requests continue without saved memory while the storage issue is repaired.

## File locations

| Scope | Location |
| --- | --- |
| Your account on this machine | `~/.config/openscience/openscience.json` or `openscience.jsonc`. |
| Project | `openscience.json` or `openscience.jsonc` in the project. |
| Project customization folder | `.openscience/` for agents, commands, skills, and related configuration. |

The resolved global location can differ with your platform or environment. Run `openscience debug paths` to find it.

JSONC permits comments and trailing commas. Use one main config file per scope to avoid conflicting settings spread across both formats.

## A small project configuration

```json
{
  "instructions": ["methods/protocol.md"],
  "skills": {
    "paths": ["./skills"]
  },
  "command": {
    "check-data": {
      "description": "Inspect data quality before analysis",
      "template": "Inspect $ARGUMENTS for missing values, duplicate rows, units, and label consistency. Keep the input unchanged."
    }
  }
}
```

Use `/check-data data/samples.csv` in the workspace, or `openscience run --command check-data "data/samples.csv"`.

## Common settings

| Key | Purpose |
| --- | --- |
| `model` | Default model in `provider/model` form. |
| `small_model` | Model for smaller helper tasks such as title generation. |
| `default_agent` | Default primary agent; Research is the normal default. |
| `provider` | Provider connections, custom endpoints, and model overrides. |
| `instructions` | Additional instruction files or patterns. |
| `skills.paths` | Extra skill directories. |
| `skills.disabled` | Skills excluded from discovery without uninstalling. |
| `command` | Reusable named prompt templates. |
| `mcp` | External tool connections. |
| `plugin` | Plugin packages or local module URLs. |
| `permission` | Action rules such as `ask`, `allow`, and `deny`. |
| `agent.<name>` | Per-agent `model`, `variant`, `skills` (categories for a specialist's domain index), `prompt`, `permission`. A rule that names a tool offers it to that agent without a skill. |
| `subagent_depth` | How many levels of workers may nest; default `1` (only the lead dispatches). |
| `harness` | Switches for the harness units, all on by default: `redirect`, `deliverables`, `budget`, `cost` (or `{ "max_usd": n }` for a soft spend ceiling), `headless-policy`, `durable-jobs`, `workers`. |
| `server.port` | Port for the local workspace or server. |
| `autoupdate` | Update preference: `true`, `false`, or `"notify"`. |

Provider and model identifiers must match the configured catalog. Use `openscience models --flat` to find them.

### Harness units

Each unit delivers one piece of context at a precise point in the loop and can be switched off with `"harness": { "<unit>": false }`:

| Unit | What it does |
| --- | --- |
| `redirect` | When the same tool failure repeats three times (or the model loops on text), inject one strategy-change message instead of stopping; a second trip stops the turn. |
| `deliverables` | When the first request names its output files, check each named file before the turn ends (present, non-empty, parses, no NaN/Inf, no placeholder text, no duplicate ids) and list the failures once; two rounds at most. |
| `budget` | Show CPUs and memory (from the container's cgroup) and, with a deadline, the time budget and elapsed time in the environment block; remind at 50% and 85%; ask to continue when time remains and deliverables fail. |
| `cost` | Show spend so far beside the time budget; an optional soft ceiling adds a wrap-up reminder, never a hard stop. |
| `headless-policy` | In `openscience run --auto-approve`, continue past denied tool calls and answer questions with their recommended option. |
| `durable-jobs` | Keep tool hints consistent with what is offered: the truncation hint suggests a worker only when delegation is on. |
| `workers` | Stream child-session events in headless runs and roll their usage into `done`. |

## Scope and overrides

Global configuration supplies defaults; project configuration can override project-specific settings. Options are combined, so adding a project setting does not mean every global setting is removed.

Some executable project customizations require approval before they become active, and administrator policy can restrict available settings. If a value seems ignored, check the setting in Customize and the applicable project or administrator configuration.

Use explicit per-run flags such as `--model` when you need to override a default for a single terminal request.

## Reference a secret

Supported configuration strings can reference an environment variable:

```json
{
  "provider": {
    "my-provider": {
      "options": {
        "apiKey": "{env:MY_PROVIDER_API_KEY}"
      }
    }
  }
}
```

This snippet shows secret substitution for an existing provider. It does not define a complete custom provider. See [Custom providers](/openscience/custom-providers).

Use a connection form or environment reference instead of committing a real key. A variable must be available to the process that starts OpenScience.

## Check changes

After editing configuration, reopen the project or restart the app if the setting does not refresh automatically. Use `openscience doctor` to check setup and read any configuration error for the file and field that need correction.

For project rules, use [Project instructions](/openscience/instructions). For external tools, use [Connectors](/openscience/connectors).
